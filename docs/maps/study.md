# Study database and JLPT question bank

1. **Entry point** — `backend/app/study/` owns the local Question Bank foundation, contracts, and markup parsing. `app.study.connection.StudyDatabaseManager` manages SQLite connections, WAL mode, and explicit transactions; `app.study.migrations.runner.run_migrations` applies forward-only SQL migrations; `app.study.backup` provides online WAL-safe backups and safe restoration.
2. **Core logic** — STRICT tables use SQLite 3.39.4+, composite foreign keys with `ON DELETE RESTRICT`, internal integer PKs with external ULIDs (`ulid.py`), and triggers that prevent mutations. `app.study.media.MediaStore` is content-addressed and atomic. `app.study.eligibility.evaluate_eligibility` returns the nine priority-ordered reason codes. `app.study.formats` defines all 20 official JLPT formats. `app.study.contracts` defines F1–F6 Pydantic discriminated unions. `app.study.markup` parses and serializes safe markup. `app.study.doctor.run_doctor` is read-only diagnostics.
3. **Ingestion and verification** — `app.study.ingestion` provides deterministic offline adapters, segmentation, classification, association, normalization, validation, review, and atomic persistence. `app.study.verification` independently solves and evaluates source-answer claims using provider abstraction, deterministic comparison, explanation generation, and non-mutating revision branching.
4. **Acquisition and learning** — `app.study.acquisition` caches raw material content-addressably, crawls deterministically, parses JapaneseTest4You, validates media, and orchestrates M3 ingestion. `app.study.session` manages practice lifecycle, deterministic grading, adaptive scheduling, elapsed time, and analytics. `app.study.exam` provides N1–N5 blueprints, readiness, timers, grading, score estimation, snapshots, and analytics.
5. **API/integration** — `backend/app/api/study/` mounts `/api/study/v1`: bank, practice, exam, analytics, diagnostics, and media. It uses ephemeral Bearer authentication, local CORS restriction, idempotent mutations, and hardened byte-range media delivery.
6. **Data/configuration** — `app.config.get_study_dir()` resolves `%LOCALAPPDATA%\\KirokuNote\\study` packaged, `backend/study/` development, or `KIROKU_STUDY_DIR`. It contains `study.db`, `media/`, and `backups/`.
7. **Strict boundaries** — `study.db` is separate from `kiroku.db`; study never syncs to cloud; study data, media, and backups are never committed or bundled. Existing vocabulary, dictionary, AnkiConnect, OCR, extension, and Electron functionality remain untouched.
8. **Tests** — target the specific `backend/tests/test_study_*.py` named by the task. Do not run the whole study suite.
